# M6 — LPV（Light Propagation Volumes）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 Crytek 2009 的 LPV —— 把场景体素化到一个低分辨率 3D 网格，每个格子用一阶 SH（4 系数）表示该处入射 radiance；以 RSM（M5 的输出）当 light injection 源；每帧迭代 N 次 6-邻居 SH 转移让光"流"过场景；着色阶段 receiver 像素查 SH 还原方向 radiance。LPV 比 VXGI 更简单 / 更便宜，但只擅长低频 diffuse；本里程碑专注于让 Sponza 这类室内场景出现明显的间接照明扩散效果。

**Architecture:**
- 新增 `LpvTechnique : IGITechnique`：
  - onAttach 分配 3D 网格资源（3 张 R/G/B 的 RGBA16F 3D image，存 SH order=1 的 4 系数；ping-pong 两套用于 propagate）。
  - prepare 每帧顺序跑：clear → inject（从 RSM 注入 SH）→ propagate 6-8 次。
  - descriptorSetLayout 把 3D image 暴露给 LightingPass 当 set=1 用。
- 新增三个 compute pass：
  - `LpvInjectPass`：从 RSM 取 VPL，转 SH 系数，atomicAdd 到对应 grid 格子（M6 起步用直接 imageStore，last-writer-wins）。
  - `LpvPropagatePass`：单次迭代，从 src grid 6 邻居读 SH，做 cosine clamp 转移到 dst grid。N 次迭代靠 App 多 dispatch（ping-pong）。
  - LPV 评估在 lighting.slang 内联做（不单独 pass）。
- LightingPass 加 LPV 的 3D image binding，在 indirect diffuse 路径加 lerp 项。

**Tech Stack:** Vulkan 1.3 (compute, 3D storage image), slang。复用 M5 的 RSM 资源做注入。

**前置条件**：M5 (RSM) 已完成 —— LPV 的 inject 阶段读取 RSM 的 (worldPos, worldNormal, flux)。如果跳过 M5，LPV 没法工作（除非自己实现某种独立的注入源，目前不在 M6 范围）。

**验证标准:**
1. **M6.0 完成**：3D 网格 inject 后能 visualize（debug pass 把某 SH 系数 → 颜色 → 体素中心位置 → 屏幕）。看到 RSM 视角范围内格子有非零 SH。
2. **M6.1 完成**：propagate N 次后光向邻居扩散。debug view 能看到光从 sun 直射区域向阴影区域"流"。
3. **M6.2 完成**：GI 下拉选 LPV，Sponza 红/绿色帘附近的白柱有色溢；光线穿透薄墙的"漏光"在可接受范围（M6 不修，标记已知瑕疵）。

**M6 不做:**
- Geometry occlusion volume（用 occluder 阻止 LPV 漏光）。M6 接受漏光，需要的话 M6.5 做。
- Cascade（多分辨率 LPV）。
- 多光源 inject（只接 RSM）。
- Glossy LPV（高阶 SH 或 GV）—— LPV 天然只做 diffuse。

**关键尺寸（默认值）:**
- LPV 网格：32 × 32 × 32（约束在 scene AABB 内）
- 每格存：R / G / B 各 4 个 SH 系数 = 4 floats × 3 通道 = 共 12 floats。三张 RGBA16F 3D image（每张 RGBA = 4 个 SH 系数对应一个色彩通道），合计：
  - 3 × 32³ × 8B = 768 KB（mip 0）
  - ping-pong 两套：1.5 MB
- Inject sample 数：从 RSM 整张图 dispatch（512² thread）；每个 RSM texel 投一个 VPL 到对应格子。
- Propagate 迭代：默认 8 次。每次 dispatch 32³ thread。

## SH order=1 速记

LPV 用一阶 SH（共 4 个 basis function）：
- Y₀₀ = 1/(2√π)
- Y₁₋₁ = √(3/(4π)) · y
- Y₁₀  = √(3/(4π)) · z
- Y₁₁  = √(3/(4π)) · x

把方向 d=(x,y,z) 上的 cosine-clamped 值投影到 SH：
```
sh.x = c * cosine_lobe;
sh.yzw = c * cosine_lobe * d * (3.0 / 2.0);
```
（具体系数见 Pixar 的 SH paper / Crytek 的 CryEngine 演讲）。LPV 转移时用 cosine lobe 把每个邻居的 SH 投到 6 个面向方向。M6 直接抄经典实现公式，不深究推导。

# M6.0 — 3D Grid + Inject from RSM

## Task 1: SH order=1 helper shader

**Files:**
- Create: `shaders/common/sh.slang`

```hlsl
// 一阶 SH (4 basis function)，cosine-weighted "lobe" 投影。
struct ShCoeffs {
    float4 c;   // (Y00, Y1-1, Y10, Y11) 系数
};

// 把方向 d 上的 cosine-clamped lobe 投到 SH。
ShCoeffs cosineLobeSh(float3 d) {
    const float A0 = 0.886226925;   // π/√(4π)
    const float A1 = 1.023326708;   // π·√(3/(4π))/(some constant)
    ShCoeffs sh;
    sh.c = float4(A0, A1*d.y, A1*d.z, A1*d.x);   // 经典系数
    return sh;
}

// 评估 SH·N（即沿方向 N 的 radiance）
float evalSh(ShCoeffs sh, float3 N) {
    float4 Nb = float4(0.282094792,                       // Y00
                       0.488602512 * N.y,                 // Y1-1
                       0.488602512 * N.z,                 // Y10
                       0.488602512 * N.x);                // Y11
    return max(0.0, dot(sh.c, Nb));
}

ShCoeffs addSh(ShCoeffs a, ShCoeffs b) { ShCoeffs r; r.c = a.c + b.c; return r; }
ShCoeffs scaleSh(ShCoeffs a, float s) { ShCoeffs r; r.c = a.c * s; return r; }
```

注：上述系数仅作示例，具体值要按经典 LPV 论文 / Crytek slides 校对。

struct LpvGrid {

## Task 3: lpv_inject.slang + LpvInjectPass

**Files:**
- Create: `shaders/gi/lpv/lpv_inject.slang`
- Create: `src/renderer/lpv_inject_pass.{h,cpp}`

inject 算法：
- dispatch RSM 分辨率（512²）。
- 每 thread 读 RSM 一个 texel，得 (worldPos, worldNormal, flux)。
- 把 worldPos 转到 grid index：`gridIdx = floor((worldPos - gridMin) / cellSize)`。
- 把 N → cosine lobe SH (4 系数) × flux → 用 imageStore 加到 lpvR/G/B 对应 cell。
  - **M6 起步**：直接 RWTexture3D[cell] = ... 用 last-writer-wins（多个 RSM texel 落到同一 cell 时丢失部分能量）。  
  - **M6.5+**：换成 atomic add（VK_FORMAT_R32_UINT pack 或 atomic float 扩展）。

```hlsl
[[vk::binding(0,0)]] Texture2D<float4> gRsmPosition;
[[vk::binding(1,0)]] Texture2D<float4> gRsmNormal;
[[vk::binding(2,0)]] Texture2D<float4> gRsmFlux;
[[vk::binding(3,0)]] RWTexture3D<float4> gLpvR;
[[vk::binding(4,0)]] RWTexture3D<float4> gLpvG;
[[vk::binding(5,0)]] RWTexture3D<float4> gLpvB;

struct InjectPC {
    uint2 rsmSize;
    uint  gridResolution;
    float3 gridMin;
    float  cellSize;
};
[[vk::push_constant]] InjectPC gPC;

[shader("compute")][numthreads(8,8,1)]
void cs_main(uint3 dt : SV_DispatchThreadID) {
    if (dt.x >= gPC.rsmSize.x || dt.y >= gPC.rsmSize.y) return;
    uint2 rpix = dt.xy;
    float3 wp = gRsmPosition.Load(int3(rpix, 0)).xyz;
    float3 wn = normalize(gRsmNormal.Load(int3(rpix, 0)).xyz);
    float3 flux = gRsmFlux.Load(int3(rpix, 0)).rgb;

    int3 idx = int3(floor((wp - gPC.gridMin) / gPC.cellSize));
    if (any(idx < 0) || any(idx >= int(gPC.gridResolution))) return;

    ShCoeffs sh = cosineLobeSh(wn);
    // last-writer-wins：直接写。后续可换 atomic add。
    gLpvR[idx] = sh.c * flux.r;
    gLpvG[idx] = sh.c * flux.g;
    gLpvB[idx] = sh.c * flux.b;
}
```

LpvInjectPass 类：
- bindFrame: 把 RSM 3 张图 + LpvGrid current() 的 3 张 3D image + LpvFrameUbo 写到 set=0。
- record: 先 vkCmdClearColorImage 清零 LpvGrid current() 三张图（避免上帧残留），再 dispatch（rsmSize/8, rsmSize/8, 1）。

# M6.1 — Propagate

## Task 5: lpv_propagate.slang

**Files:**
- Create: `shaders/gi/lpv/lpv_propagate.slang`

算法（每次迭代）：
- dispatch grid resolution³（32³）。
- 每 thread = 一个目标 cell。
- 从 src grid 读自己 cell 的 SH + 6 个邻居（±x, ±y, ±z）的 SH。
- 对每个邻居，用 cosine lobe 把它的 SH 转移到当前 cell 的 6 个面向方向之一（朝向当前 cell）。
- 把 6 个邻居的转移结果累加，写到 dst grid。

```hlsl
[[vk::binding(0,0)]] Texture3D<float4> gSrcR;
[[vk::binding(1,0)]] Texture3D<float4> gSrcG;
[[vk::binding(2,0)]] Texture3D<float4> gSrcB;
[[vk::binding(3,0)]] RWTexture3D<float4> gDstR;
[[vk::binding(4,0)]] RWTexture3D<float4> gDstG;
[[vk::binding(5,0)]] RWTexture3D<float4> gDstB;

struct PropagatePC {
    uint gridResolution;
    float occlusionAmplifier;   // 默认 1.0；扩展用
};

const int3 kNeighborOffsets[6] = {
    int3(+1,0,0), int3(-1,0,0), int3(0,+1,0), int3(0,-1,0), int3(0,0,+1), int3(0,0,-1)
};

[shader("compute")][numthreads(4,4,4)]
void cs_main(uint3 dt : SV_DispatchThreadID) {
    if (any(dt >= uint3(gPC.gridResolution))) return;

    float4 sumR = 0, sumG = 0, sumB = 0;
    for (int i = 0; i < 6; ++i) {
        int3 nIdx = int3(dt) - kNeighborOffsets[i];   // 邻居坐标
        if (any(nIdx < 0) || any(nIdx >= gPC.gridResolution)) continue;

        float4 nR = gSrcR.Load(int4(nIdx, 0));
        float4 nG = gSrcG.Load(int4(nIdx, 0));
        float4 nB = gSrcB.Load(int4(nIdx, 0));

        // 经典 LPV propagation：邻居 SH × cosine lobe 朝向当前 cell × solid angle。
        // 系数从 Crytek slide。这里仅用伪代码 —— 实现时按论文公式填准。
        float3 dirToHere = float3(kNeighborOffsets[i]);   // 粗略
        // ... 用 cosineLobeSh(dirToHere) 与邻居 SH 做点积合成 ...
    }

    gDstR[dt] = sumR;
    gDstG[dt] = sumG;
    gDstB[dt] = sumB;
}
```

**实现注意**：propagate 公式有完整的"6 面向 cosine lobe 投到 SH，乘 solid angle，转移给目标 cell"的标准推导。M6 严格抄 Crytek slides 或 Kaplanyan 2010 的实现。

m_inject.record(...);

## Task 8: lighting.slang 评估 LPV

**Files:**
- Modify: `shaders/lighting/lighting.slang`

加 binding 10/11/12 = `gLpvR/G/B` (Texture3D<float4>) + LpvUbo（携带 gridMin / cellSize / gridResolution）。

在 `if (counts.z != 0)` 路径里，receiver 像素：
1. worldPos → grid coord：`(worldPos - gridMin) / cellSize`。
2. trilinear 取 SH（slang `Texture3D.Sample` 自动 trilinear，需 sampler）。
3. evalSh(shR, N), evalSh(shG, N), evalSh(shB, N) → 三通道 radiance。
4. 乘 albedo, kd, intensity → 加到 diffuse。

混合策略：counts.z 编码扩展为 4 = LPV。
```hlsl
if (counts.z == 4) {
    float3 lpvDiff = applyIBLDiffuseBRDF(lpvRadiance, ...);
    diffuse = lerp(iblDiff, lpvDiff, lpvCoverage);
}
```
